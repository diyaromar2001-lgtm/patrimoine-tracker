ROOT CAUSE: MISSING OPERATION TYPE HANDLERS
═════════════════════════════════════════════════════════════════════════════

PROBLEM 1: Parser does not map specialized dividend types
─────────────────────────────────────────────────────────
Current parser (test-import-trading212-final.js, line 95-102):

  if (actionLower.includes('buy')) type = 'buy';
  else if (actionLower.includes('sell')) type = 'sell';
  else if (actionLower.includes('dividend')) type = 'dividend';
  else if (actionLower.includes('interest')) type = 'interest';
  ...

Issue: Maps:
  - "Dividend (Dividend)" → 'dividend' ✅
  - "Dividend (Tax exempted)" → 'dividend' ⚠️ (wrong type)
  - "Dividend adjustment" → 'dividend' ⚠️ (wrong type)

Should map:
  - "Dividend (Dividend)" → 'dividend'
  - "Dividend (Tax exempted)" → 'dividend_tax_exempted'
  - "Dividend adjustment" → 'dividend_adjustment'

PROBLEM 2: RPC does not handle specialized dividend types
──────────────────────────────────────────────────────────
Current RPC (import-schema-trading212-final.sql, line 723-772):

  ELSIF v_op_type = 'dividend' THEN
    ... (handles only regular dividend)
  ELSE
    RAISE EXCEPTION 'Unknown operation type: %...', v_op_type;

If parser sends 'dividend_tax_exempted' or 'dividend_adjustment':
  → RPC raises EXCEPTION
  → ENTIRE BATCH FAILS (atomic rollback)
  → 0 operations imported

PROBLEM 3: Stock split operations create no transactions
────────────────────────────────────────────────────────
Stock splits are processed in first loop (line 556-589) but:
  - Create entries in stock_split_events table only
  - Do NOT create transaction rows
  - Do NOT increment v_rows_imported counter
  - Result: 2 splits NOT counted as imported operations
